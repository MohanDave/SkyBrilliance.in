An agent pipeline that watches your numbers, and shows its work.

Sentinel reads your business metrics, flags what changed, and explains why in plain language. It is built as three separate agents rather than one model doing everything, so the part that decides what is true is code you can read, not a prompt you have to trust.

Three agents, three jobs

No single model is responsible for both deciding what is true and deciding how to say it.

Most AI analytics tools run one model over your data and hand you a paragraph. If that model gets the interpretation wrong, there is no way to tell without redoing the analysis yourself. Sentinel splits the work into a pipeline instead, so the step that actually decides whether something is unusual never touches a language model at all.

Agent 1 LLM

Clean and sanity-check

Takes a raw CSV of business metrics, catches formatting issues, missing fields, and obvious data errors before anything downstream sees it.

Agent 2 Deterministic

Detect the anomaly

Rolling mean and standard-deviation analysis, no model involved. Same input always produces the same flagged anomalies, fully auditable.

Agent 3 LLM

Narrate the finding

Turns a statistical flag into a plain-English explanation of what moved, by how much, and why it is worth a look.

Why split it up

Language models are good at understanding messy input and writing clear output. They are not the right tool for deciding, with consistency, whether a number is statistically unusual. Sentinel uses each type of system for what it is actually good at.

What that buys you

If Sentinel flags something, you can look at Agent 2's output directly and see the exact calculation behind it. Nothing about whether an anomaly happened depends on a model's judgment call.

Where it stops

Sentinel tells you what changed and gives you a plain-language read on it. It does not make decisions on your behalf. A person still decides what to do next.

What it's built on

Kept small on purpose.

Core language

Python standard library. The anomaly detection layer does not depend on external packages, which keeps it easy to read and easy to audit.

Language model

Anthropic's Claude, called only where language understanding is genuinely needed: cleaning input and writing the plain-English explanation.

Access control

API calls are gated behind an environment variable, so the deterministic core can run and be reviewed independently of any model access.
